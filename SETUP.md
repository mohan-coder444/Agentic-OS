# Cortex AI — Multi-Agent Platform (your build)

Scaffold following the YouTube tutorial (Hours 1-9). Microservices: one Node/Express
server per service, all reached through a single API **gateway**.

## Layout
```
backend/
  gateway/        # port 8000 — entry point; proxies /auth, /chat, /agent
  services/
    auth/         # port 8001 — Google auth (Firebase) + User model + JWT sessions (lax)
    chat/         # port 8002 — conversations + messages + Redis memory (last 20)
    agent/        # port 8003 — LangGraph router (Groq) + 6 agents (Groq/Mistral) + Vector DB (RAG) + S3
    billing/      # (later) credits + Razorpay
  shared/
    redis/        # ioredis + in-memory fallback (shared via JWT)
    s3/           # S3 upload (mock if no AWS keys, watermark: Generated by Cortex AI)
frontend/         # React + Vite + Tailwind + Firebase + Redux + Chat UI (indigo)
```

## Run the full stack (gateway + auth + chat + agent + frontend)
```bash
# terminal 1 — gateway
cd backend/gateway
npm install
npm run dev    # -> http://localhost:8000

# terminal 2 — auth
cd backend/services/auth
npm install
npm run dev    # -> http://localhost:8001 (via gateway /auth)

# terminal 3 — chat
cd backend/services/chat
npm install
npm run dev    # -> http://localhost:8002 (via gateway /chat)

# terminal 4 — agent
cd backend/services/agent
npm install
npm run dev    # -> http://localhost:8003 (via gateway /agent) — needs GROQ_API_KEY + MISTRAL_API_KEY in .env

# terminal 5 — frontend
cd frontend
npm install
npm run dev    # -> http://localhost:5173
```
- `GET http://localhost:8000/api`           -> { message: "Hello from Gateway" }
- `GET http://localhost:8000/auth/api`      -> { message: "Hello from Auth" }
- `GET http://localhost:8000/chat/api`      -> { message: "Hello from Chat" }
- `GET http://localhost:8000/agent/api`     -> { message: "Hello from Agent" }
- `POST http://localhost:8000/agent/run`    -> { aiResponse, route } (Groq/Mistral + RAG)

## Docker (optional, for production parity)
```bash
# Requires Docker Desktop
# Set REDIS_URL and AWS keys in .env files first

docker compose up --build -d   # starts redis + gateway + auth + chat + agent
# Frontend still runs via vite (or add it to compose)

# Check logs
# docker compose logs -f gateway
```
- `docker-compose.yml` at project root defines `redis:7-alpine` + 4 Node services, all on `REDIS_URL=redis://redis:6379`.
- Each service has a `Dockerfile` (node:20-alpine, `npm ci`, `EXPOSE 800x`).

## S3 (for PDF/PPT)
- `backend/shared/s3/s3.js` uses `@aws-sdk/client-s3`. Set in `agent/.env`:
  ```
  AWS_ACCESS_KEY_ID=...
  AWS_SECRET_ACCESS_KEY=...
  AWS_REGION=ap-south-1
  AWS_S3_BUCKET=cortex-ai-pdfs
  ```
- Without keys, it mocks: `https://mock-s3.local/pdfs/...` with watermark `Generated by Cortex AI` (as in tutorial's PDF expiry 10 min).

## To make the DB + auth actually work, fill in credentials:
1. **MongoDB Atlas** — create a free cluster, a DB user, and set
   *Network Access* to `0.0.0.0/0`. Paste the connection string into
   `backend/services/auth/.env` as `MONGO_URI=.../auth`.
2. **Firebase** — create a project + Web app. In *Project settings → Service
   accounts*, click **Generate new private key**, save the JSON as
   `backend/services/auth/serviceAccountKey.json`. Firebase auto-initializes.

## Notes
- Express is v5; the gateway uses `express-http-proxy` exactly like the tutorial.
  If it ever misbehaves on v5, swap it for `http-proxy-middleware` (same idea).
- Each service owns its own routes; the gateway only strips the `/auth` prefix.
